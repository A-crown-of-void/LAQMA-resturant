# لَقمة | LAQMA — Navy & Coral

واجهة تجريبية لإدارة مطعم وطلب الطعام، مبنية باستخدام React 18 وVite 6.

## التشغيل
```bash
npm install
npm run dev
```
ولإنشاء نسخة الإنتاج: `npm run build` ثم `npm run preview`.

## الوظائف الموجودة في هذه النسخة
- واجهة زبون لتصفح القائمة والبحث والتصنيفات وإضافة المنتجات إلى السلة.
- سلة تدعم تعديل الكميات وإزالة الأصناف، وإتمام طلب مع الهاتف والعنوان أو الاستلام وملاحظات.
- رمز خصم تجريبي وخيارات دفع تجريبية مع حالة مراجعة شام كاش.
- متابعة طلبات الزبون محلياً عبر رقم الهاتف على المتصفح نفسه.
- إدارة المنتجات: إضافة وتعديل وحذف وتغيير التوفر والسعر والوصف والتصنيف والصورة.
- رفع صورة حقيقية من الجهاز، معاينتها وضغطها قبل الحفظ؛ لا يتم تعيين صورة عامة تلقائياً للمنتج الجديد.
- لوحات الطلبات والمطبخ والتوصيل وتعيين مندوب من الموظفين وطباعة فاتورة.
- الحجوزات مع الإضافة والتأكيد وتعيين طاولة والتحقق من تعارض الطاولة والموعد.
- المخزون وتسجيل التوريد، الموردون والمشتريات، الوصفات وتكلفة مكونات الطبق.
- الموظفون، تسجيل الدوام، تسجيل دفعات الرواتب، الأصول والصيانة.
- المصروفات والصندوق، الكوبونات والولاء، الدعم، الإشعارات، الإعدادات والتقارير وتصدير CSV.
- واجهة متجاوبة محسنة للهواتف، بألوان Navy & Coral.

## حدود مهمة — اقرأ قبل الاستخدام
هذه نسخة Frontend تجريبية. البيانات محفوظة في LocalStorage على الجهاز والمتصفح الحاليين فقط. لا يوجد خادم أو قاعدة بيانات مركزية أو مصادقة آمنة أو صلاحيات محمية على الخادم. لذلك لن تتزامن الطلبات بين هاتف الزبون وجهاز المطعم أو بين أجهزة الموظفين. لا تستخدمها لتشغيل مطعم فعلي أو حفظ بيانات حساسة.

رفع الصور يخزن نسخة مضغوطة داخل تخزين المتصفح؛ قد يصل التخزين إلى الحد الأقصى عند إضافة صور كثيرة. شام كاش ليس تكاملاً مصرفياً؛ الحالة مراجعة يدوية تجريبية ولا يحدث تحصيل تلقائي. خصم المخزون حسب الوصفة يعمل فقط للمنتجات التي أضيفت لها مكونات وصفة، ولا ينبغي اعتباره محاسبة مخزون نهائية. الرواتب والدوام والمشتريات والولاء والكوبونات والأصول والصيانة وحدات أولية تحتاج قواعد تشغيل واعتمادات وتدقيقاً قبل الإنتاج. صور الأطباق الحالية تستخدم روابط صور خارجية؛ يفضّل تنزيل الصور المرخصة إلى مجلد assets أو CDN مملوك للمطعم لضمان عدم اختفائها.

## قبل النشر الفعلي
إنشاء Backend وقاعدة بيانات (مثل PostgreSQL) وواجهات API، وتسجيل دخول لكل مستخدم مع صلاحيات على الخادم، وتخزين صور دائم، وربط الدفع والرسائل والطباعة ومزامنة الأجهزة، ثم اختبارات end-to-end وأمن ونسخ احتياطي.


## إضافات هذه النسخة

- **الطلب عبر QR:** صفحة رموز QR لـ 12 طاولة، يفتح كل رمز قائمة الزبون مع رقم الطاولة في الطلب. صور QR حالياً تُنشأ عبر خدمة خارجية (QR Server)، ويجب استبدالها بمولّد QR محلي أو خدمة معتمدة قبل الإطلاق.
- **تتبع التوصيل:** يستطيع المندوب بدء مشاركة الموقع الحي من المتصفح، وتُحدّث إحداثيات الطلب أثناء المشاركة، ويمكن للعميل عرض آخر موقع محفوظ على الخريطة. يتطلب HTTPS وإذن الموقع.
- **مراقبة الهدر:** تسجيل المادة والكمية والسبب والتكلفة، مع خصم الكمية من المخزون وإظهار إجمالي تكلفة الهدر.
- **صلاحيات الواجهة:** أضيفت أدوار الاستقبال والكاشير والطاهي والمندوب والمخزون والنادل والزبون، مع تقييد صفحات الواجهة وإجراءات تغيير حالة الطلب حسب الدور.

## حدود أمنية وتشغيلية مهمة

هذه ما تزال نسخة Frontend تجريبية تعتمد على LocalStorage. قائمة تبديل الأدوار مخصصة لاختبار الواجهات وليست تسجيل دخول آمنًا؛ لا يمكن اعتبار الصلاحيات حماية فعلية ما دامت البيانات والقرارات في المتصفح. يجب قبل الاستخدام الحقيقي إنشاء Backend وقاعدة بيانات ومصادقة مستقلة لكل موظف، والتحقق من الصلاحيات على الخادم لكل API، وتخزين سجلات المواقع والطلبات مركزيًا.

التتبع المباشر يُحفظ في المتصفح الذي يشغّل لوحة المطعم فقط؛ لا تتم مزامنته تلقائيًا إلى هاتف العميل أو جهاز آخر من دون Backend/Realtime service. لذلك يستطيع العميل في هذه النسخة مشاهدة آخر إحداثيات متاحة فقط إذا كانت بياناته على المتصفح نفسه. كذلك لا ترسل QR الطلبات إلى أجهزة المطعم الأخرى ما لم تتم إضافة خادم.

## تحديث قاعدة بيانات العرض (أكتوبر 2026)
- تُنشأ تلقائياً 100 عينة تجريبية على الأقل في كل قسم تشغيلي ذي سجلات: الطلبات، المنتجات، المكونات، الحجوزات، الموظفون، المصروفات، التذاكر، الإشعارات، الموردون، المشتريات، الوصفات، الورديات، الأصول، الصيانة، الكوبونات، الولاء، حركات الصندوق، وسجلات الهدر.
- أضيفت 100 طاولة/رابط QR في صفحة رموز الطاولات.
- أضيفت أدوات تصدير واستعادة نسخة احتياطية بصيغة JSON من صفحة الإعدادات.
- البيانات المولدة مخصصة للاختبار فقط، وليست بيانات مطعم حقيقية. يتم الحفاظ على البيانات المحفوظة الموجودة قدر الإمكان وإضافة عينات تجريبية عند الحاجة للوصول إلى 100 سجل.
- تنبيه: التطبيق ما زال نموذجاً أمامياً يعتمد LocalStorage. لا يوفر بعد قاعدة بيانات مشتركة، أو حسابات آمنة، أو بثاً آنياً حقيقياً بين الأجهزة، أو تحصيل دفع فعلي. لا تستخدمه لتشغيل مطعم فعلي قبل بناء الخادم والمصادقة والتكاملات واختبارات الأمان.


## كتالوج المنتجات التجريبي الإضافي
تمت إضافة 50 منتجاً تجريبياً إضافياً موزعة بالتساوي على 10 تصنيفات: الشاورما، الزنجر والبرغر، الدجاج والبروستد، المشاوي، المقبلات، الإضافات، الصلصات، المشروبات، الحلويات، ووجبات الأطفال والعائلات. لكل منتج اسم وسعر ووصف وصورة مبدئية قابلة للتعديل من إدارة القائمة. البيانات لأغراض الاختبار فقط.

## تنبيه مهم حول البيانات والصلاحيات
- أزيلت سجلات الاختبار المولّدة آلياً ذات الأسماء مثل "موظف تجريبي" و"مورد تجريبي". تبدأ النسخة بسجلات قليلة، مع قائمة منتجات قابلة للتعديل.
- أسماء العملاء والموظفين الموجودة في بيانات البداية أمثلة توضيحية وليست سجلات أشخاص حقيقيين. لا يجوز اختلاق بيانات شخصية حقيقية أو نسبها إلى أشخاص. أدخل بيانات مطعمك الحقيقية بموافقة أصحابها.
- أضيفت شاشة دخول جلسة العرض، وأزيل مبدّل الدور من الشريط العلوي، وأصبح تسجيل الخروج ينهي الجلسة الحالية ويمسح بيانات العميل المؤقتة من المتصفح.
- هذه القيود والصلاحيات على الواجهة فقط. لا تستخدم النسخة الحالية لحماية بيانات حقيقية أو تشغيل حسابات موظفين؛ يلزم Backend وقاعدة بيانات ومصادقة خادمية وتفويض لكل API، مع جلسات آمنة وسجل تدقيق.
